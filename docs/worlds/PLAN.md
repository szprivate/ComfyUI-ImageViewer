# Worlds from reference images — plan

Walkable, game-like worlds (no game actions) built from one or more reference
images, generated by ComfyUI or by an agent, viewed and walked in the bEpic
viewer, with the user's feedback going back to whoever built them.

## The split

Two repos, one contract between them.

| | **ComfyUI-ImageViewer** (this repo, branch `worlds`) | **ComfyUI-bEpicWorlds** (new repo) |
|---|---|---|
| Role | *shows* a world: renders, walks, compares, collects feedback | *makes* a world: reads references, generates terrain, textures, layout; edits and versions it |
| Language | JS (three.js), plus two small server hooks | Python (numpy + Pillow), a ComfyUI node pack, an MCP server, a CLI |
| Depends on the other? | no — reads the scene schema, posts feedback if the worlds routes answer | no — writes the scene schema, tells the viewer to open it over the existing `bepic.viewer.update` message |

The contract is the **scene schema** — the viewer's existing previz scene
(`bEpicViewer_scene3d.js`) plus the world item kinds below. It is documented in
the worlds repo as `SCHEMA.md`, and the viewer's `parseScene` is the reference
reader.

Why two repos: world generation will grow heavy dependencies and vendored code
the viewer's ~274 installs don't need, and the registry scan has already shown
what extra surface costs. It is also what lets an agent use the world builder
without the viewer being involved at all.

## Scene schema additions (v1)

All items keep the standard transform (`position`, `rotation`, `scale`,
`pivot`, `parent`, `visible`, `tracks`).

- `environment` — one per world. `sky` {mode: gradient|panorama, top, horizon,
  bottom, src}, `sun` {azimuth, elevation, color, intensity, shadows}, `fog`
  {color, density}, `ambient`. Replaces the default studio light rig while present.
- `terrain` — `heightmap` src (8-bit grey, or `rg16`: height = (R·256+G)/65535),
  or procedural {seed, roughness} when there is none; `size` [x, z], `height`,
  `segments`; up to four `layers` {src?, color, tile}, blended by slope and
  height (`rules`), or by a `splat` src.
- `scatter` — instances over a terrain: `target` (terrain id), `source`
  {type: pine|tree|bush|grass|rock|model, src?}, `count`, `seed`, `scale`
  [min, max], `layer` (which terrain layer it grows on), `maxSlope`, `color`,
  `wind`.
- `depthmesh` — a picture pushed out by its depth map: `src`, `depth`, `fov`,
  `near`, `far`, `cut` (tear threshold at depth edges), `invert`. Drawn unlit;
  it is the reference view, reproduced.
- camera `reference` — {src, opacity, wipe}: the picture this view has to match,
  drawn over the gate when looking through it.
- scene `walk` — {spawn, yaw, eyeHeight, speed, bounds}.
- scene `world` — {name, version, feedback[]}: which world this is, and the
  feedback pins to draw.

## Pieces, and what is built now

✅ built in this pass · ◻ planned

### Viewer (branch `worlds`)
- ✅ Schema: the kinds above, parsed and defaulted in `parseScene`.
- ✅ Renderer (`bEpicViewer_world3d.js`): environment (gradient or panorama sky,
  sun with shadows, fog), terrain (heightmap or procedural, 4-layer blend),
  scatter (instanced, procedural plants and rocks or a model, wind sway),
  depth mesh (torn at depth edges, unlit).
- ✅ Walk mode: pointer-lock look, WASD, run, ground-following on terrain and
  meshes, bounds; a toolbar button and a rebindable hotkey.
- ✅ Reference overlay on cameras, with opacity and a wipe, for match checking.
- ✅ Add → World menu; world parameters in the channel box.
- ✅ Feedback pins: click a spot, write a note; saved with the camera view and a
  snapshot, sent to the worlds routes, drawn as pins until resolved.
- ✅ `bepic.viewer.update` learns `scene_replace` and `tab_label`, so a world
  sent again replaces the old one and an agent can open a tab with no node.
- ◻ Video textures (cinemagraph regions), water, particles, audio zones.
- ◻ Gaussian splats (vendored renderer; ComfyUI-Sharp is already installed and
  makes them from one image).
- ◻ Streaming/LOD for large worlds; collision against props (three-mesh-bvh).
- ◻ Standalone export (a world as a self-contained page).

### Worlds repo (`ComfyUI-bEpicWorlds`)
- ✅ `bepic_worlds` library (numpy + Pillow only):
  - `reference` — palette, sky/horizon/ground colours, horizon line → camera
    pitch, sun direction and colour from the bright region.
  - `spec` — a world spec from JSON or plain text (biome, time of day, fog,
    scatter), with biome presets.
  - `terrain` — procedural heightmaps (fBm, flat where you start, rising
    toward the far distance), `rg16` encoding.
  - `textures` — tileable ground textures cut from the reference itself.
  - `builder` — reference + spec (+ optional depth, heightmap, panorama) → a
    complete world scene and its assets.
  - `store` — a world is a folder: `world.json`, `versions/`, `assets/`,
    `feedback.jsonl`. Edit operations, versioning, feedback.
- ✅ ComfyUI nodes: **bEpic World From Reference**, **bEpic World Feedback**.
- ✅ Routes: open a world in the viewer, post/list/resolve feedback, list
  worlds — POST for anything that changes something, confined to
  `output/worlds`, nothing that starts a process.
- ✅ Agent interface: an MCP server (`python -m bepic_worlds.mcp_server`) and a
  CLI (`python -m bepic_worlds …`) over the same operations: create, describe,
  edit, list/resolve feedback, open in viewer.
- ◻ Multi-reference worlds (a reference per region/camera), VLM-written specs
  as a node input from any VLM node, image-to-3D props placed from reference
  crops, splats via ComfyUI-Sharp.

## The feedback loop

1. Agent: `create_world(reference, spec)` → a world folder, version 1.
2. Agent: `open_in_viewer(name)` → the viewer opens a `World: name` tab.
3. You walk it, and drop pins: "fewer trees here", "sky too saturated".
   Each pin keeps its 3D point, the camera it was seen from and a snapshot.
4. Agent: `get_feedback(name)` → open pins, with snapshots it can look at.
5. Agent: `edit_world(name, ops)` → version 2; `resolve_feedback(ids, version)`.
6. Back to 2. Resolved pins disappear; every version is kept.
